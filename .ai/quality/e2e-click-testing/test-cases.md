# 同步任务模块测试用例基线文档

## 1. 文档定位

本文档用于沉淀 DolphinScheduler 二开“同步任务”模块的测试用例基线，作为后续每次开发、自测、回归和交付时必须参考的测试清单。

目标不是只记录“测一下流程”，而是把：

- 哪些功能必须测
- 哪些场景必须覆盖
- 哪些异常必须验证
- 哪些 Dolphin 原生功能必须回归
- 哪些结果必须截图、记录、说明

全部固化下来。

后续同步任务模块开发，应遵循以下顺序：

1. 先修改需求文档
2. 再修改测试用例文档
3. 再进入代码开发
4. 最后按本文档执行真实点击测试

## 2. 测试总体原则

### 2.1 核心原则

- 必须使用模拟人类逐步点击页面的方式测试。
- 不能只看代码。
- 不能只跑构建。
- 不能只跑接口。
- 不能只验证 Happy Path。
- 不能只验证同步任务自身，还必须验证未破坏 Dolphin 原生能力。

### 2.2 测试层次

每次交付前，至少需要执行以下四层测试：

1. 页面功能路径测试
2. 前后端接口链路测试
3. 异常与边界场景测试
4. 原生功能保护回归测试

### 2.3 测试记录要求

每次测试至少记录：

- 测试日期
- 测试人 / 执行主体
- 代码版本或本轮修改点
- 覆盖的测试用例编号
- 测试结果：通过 / 失败 / 阻塞
- 失败现象
- 修复后复测结果

## 4. 用例分级

### 4.1 P0 用例

阻塞交付的关键用例，任何一个失败都不能交付。

### 4.2 P1 用例

重要功能用例，应在每次中大型改动后执行。

### 4.3 P2 用例

增强体验或边界兼容性用例，可按改动范围选择性执行。

## 5. P0 主流程用例

### TC-P0-001 页面可正常进入

#### 目标

验证同步任务页面可以从导航进入，并正常渲染。

#### 前置条件

- 系统服务正常启动
- 已成功登录

#### 操作步骤

1. 进入 DolphinScheduler 首页
2. 点击左侧导航“同步任务”

#### 预期结果

- 成功进入 `/ui/sync-task`
- 页面显示 4 步流程
- 页面无明显报错
- 页面内容无空白或崩溃

### TC-P0-002 第 1 步基础配置可完成

#### 目标

验证项目、源端、目标端的基础选择可以完成。

#### 操作步骤

1. 选择项目 `test1`
2. 选择源数据源 `mysql_case_workbench`
3. 选择源数据库 `case_workbench`
4. 选择源表 `ajxx_tab`
5. 选择目标数据源 `pgsql_test1`
6. 选择目标数据库 `test1`
7. 填写 Schema `public`
8. 填写目标表名

#### 预期结果

- 源库列表成功加载
- 源表列表成功加载
- 目标库列表成功加载
- 页面没有要求用户重复输入源端/目标端密码
- 点击“下一步”可进入第 2 步

### TC-P0-003 第 2 步字段元数据正确展示

#### 目标

验证源字段元数据读取和展示正确。

#### 操作步骤

1. 完成第 1 步
2. 进入第 2 步

#### 预期结果

- 能看到源字段列表
- 字段名展示正常
- 源字段类型不是 `unknown`
- 字段注释正常显示，无乱码
- 主键信息正常显示
- 可空信息正常显示

### TC-P0-004 第 2 步字段勾选能力完整可用

#### 目标

验证字段选择能力完整可用。

#### 操作步骤

1. 进入第 2 步
2. 只勾选 1 个字段
3. 再勾选第 2 个字段
4. 点击“全选字段”
5. 点击“反选字段”
6. 点击“清空选择”
7. 再次只勾选部分字段

#### 预期结果

- 单个勾选有效
- 部分勾选有效
- 全选有效
- 反选有效
- 清空有效
- 不会出现“只能全选、不能部分选”的问题

### TC-P0-005 第 2 步目标字段自动生成正确

#### 目标

验证勾选源字段后，目标字段能自动生成。

#### 操作步骤

1. 在第 2 步勾选部分源字段

#### 预期结果

- 目标字段区自动生成对应行
- 默认目标字段名正确
- 默认目标类型已推荐
- 默认注释继承合理
- 主键与可空默认值合理

### TC-P0-006 第 2 步连线映射可拖拽

#### 目标

验证字段映射可通过拖拽连线调整。

#### 操作步骤

1. 在第 2 步勾选至少 2 个字段
2. 从左侧源字段锚点拖到右侧目标字段
3. 从右侧目标字段锚点反向拖到左侧源字段
4. 观察连线交叉效果

#### 预期结果

- 左侧可拖
- 右侧可拖
- 连线可以成功建立或改绑
- 连线交叉时仍清晰可见
- 连线不会被字段面板遮挡
- 映射来源文案随之更新

### TC-P0-007 第 3 步 DDL 预览和确认建表可用

#### 目标

验证 DDL 预览、编辑和执行链路可用。

#### 操作步骤

1. 完成第 2 步有效字段配置
2. 进入第 3 步
3. 点击“生成建表语句”
4. 检查 DDL 内容
5. 修改 DDL 部分内容
6. 点击“确认建表”

#### 预期结果

- 成功生成 DDL
- DDL 中包含目标表结构
- DDL 中包含主键信息
- DDL 中包含注释信息
- DDL 文本可编辑
- 点击“确认建表”后才真正执行建表
- 建表成功有清晰反馈

### TC-P0-008 第 4 步配置预览可查看可编辑

#### 目标

验证 SeaTunnel 配置预览浮层可正常工作。

#### 操作步骤

1. 点击全局“查看配置预览”
2. 查看生成内容
3. 编辑配置内容
4. 关闭后再次打开

#### 预期结果

- 只存在一个全局预览入口
- 能看到自动生成的 SeaTunnel 配置
- 配置可编辑
- 编辑结果可保留或可重置

### TC-P0-009 保存同步任务可成功

#### 目标

验证同步任务可保存为 DolphinScheduler 工作流。

#### 操作步骤

1. 完成前 3 步有效配置
2. 进入第 4 步
3. 点击“保存同步任务”

#### 预期结果

- 保存成功
- 后端成功创建或更新工作流定义
- 页面反馈工作流编码或相关成功信息

### TC-P0-010 保存并执行可真正运行

#### 目标

验证“保存并执行”可以真正触发同步运行。

#### 操作步骤

1. 完成有效同步任务配置
2. 点击“保存并执行”

#### 预期结果

- 先保存工作流
- 再上线工作流
- 再启动实例
- 页面展示提交状态
- 页面展示实例状态
- 页面展示节点状态
- 页面展示同步数据量

### TC-P0-011 同步数据量显示正确

#### 目标

验证成功态下能显示真实同步数据量。

#### 操作步骤

1. 完整执行同步任务
2. 等待实例成功

#### 预期结果

- 页面显示“同步数据量”
- 数据量来自真实日志或真实统计
- 不是写死、估算或假值

## 6. P1 重要功能用例

### TC-P1-001 目标表已存在场景

#### 目标

验证目标表已存在时不会误报连接错误。

#### 操作步骤

1. 使用已存在的目标表名
2. 执行“确认建表”

#### 预期结果

- 页面明确提示目标表已存在或已跳过
- 不应误报“建立数据源连接失败”

### TC-P1-002 第 3 步周期调度可独立配置

#### 目标

验证周期调度配置入口不被无关前置条件拦死。

#### 操作步骤

1. 进入第 3 步
2. 点击配置周期调度

#### 预期结果

- 能打开周期调度配置
- 配置方式接近原生“定时”交互
- 不要求用户手写复杂表达式

### TC-P1-003 第 4 步运行结果留在当前页展示

#### 目标

验证保存并执行后用户不会失去上下文。

#### 操作步骤

1. 点击“保存并执行”

#### 预期结果

- 默认留在当前页
- 当前页展示提交与运行状态
- 允许通过节点名称进入实例详情
- 不强制突兀跳走

### TC-P1-004 第 2 步字段映射影响 DDL 和配置生成

#### 目标

验证字段映射变更会同步影响后续结果。

#### 操作步骤

1. 在第 2 步调整映射关系
2. 进入第 3 步生成 DDL
3. 打开配置预览

#### 预期结果

- DDL 使用最新映射关系
- 配置预览使用最新映射关系
- 运行时使用最新映射关系

### TC-P1-005 目标字段属性修改生效

#### 目标

验证目标字段的类型、注释、主键、可空修改有效。

#### 操作步骤

1. 修改目标字段类型
2. 修改目标字段注释
3. 调整主键
4. 调整可空
5. 生成 DDL

#### 预期结果

- DDL 中正确反映这些修改
- 配置预览中的目标字段定义与页面一致

## 7. P2 边界与体验用例

#### 预期结果

### TC-P2-002 第 2 步在常见分辨率下可完整操作

#### 目标

验证字段区在常见笔记本屏幕中不会被遮挡。

#### 参考分辨率

#### 预期结果

- 第 2 步字段区可完整滚动和操作
- 不被底部按钮遮挡

### TC-P2-003 配置预览编辑后可回退

#### 目标

验证手工编辑 SeaTunnel 配置后可恢复为系统生成值。

### TC-P2-004 空状态显示稳定

#### 目标

验证无字段、无目标字段、无运行结果时页面不塌陷。

#### 预期结果

- 空状态文本不竖排
- 面板宽度稳定
- 操作提示简洁

## 8. 异常场景用例

### TC-ERR-001 字段类型不能显示为 unknown

#### 目标

防止源字段类型再次退化为 `unknown`。

### TC-ERR-002 不应要求页面重复输入密码

#### 目标

防止再次出现“源端密码为空，请在页面补充”。

### TC-ERR-003 进入页面不能出现 NaN 导致的服务端异常

#### 目标

防止再次出现：

- `Failed to convert value of type 'java.lang.String' to required type 'long'`
- `For input string: "NaN"`

### TC-ERR-004 保存并执行后不能无响应

#### 目标

防止点击执行后页面没有任何结果反馈。

### TC-ERR-005 第 3、4 步必须可切换

#### 目标

防止因为前端节点复用或校验逻辑，导致第 3、4 步内容切不出来。

3. 在工作流列表右侧点击“定时”

#### 预期结果

- 原生定时弹框正常打开
- 原生定时功能正常可用

### TC-REG-002 运行实例页正常

#### 目标

验证实例页没有被同步任务功能影响。

### TC-REG-003 源中心、项目管理菜单正常

#### 目标

验证导航和原有菜单功能未受破坏。

## 10. 接口链路核验点

每次 P0 测试时，至少要观察或记录以下接口链路：

- `/datasources/tableColumnMetas`
- `/datasources/preview-target-table`
- `/datasources/create-target-table`
- `/projects/{projectCode}/workflow-definition`
- `/projects/{projectCode}/workflow-definition/{code}/release`
- `/projects/{projectCode}/executors/start-workflow-instance`

预期：

- 字段元数据接口返回真实字段信息
- DDL 预览接口成功返回建表语句
- 建表接口成功执行或返回“已存在”可识别状态
- 工作流定义创建 / 更新成功
- 工作流上线成功
- 工作流实例启动成功

## 11. 每次开发后的最小回归集

后续每次开发完成后，至少执行以下最小回归集：

1. TC-P0-001
2. TC-P0-002
3. TC-P0-003
4. TC-P0-004
5. TC-P0-006
6. TC-P0-007
7. TC-P0-008
8. TC-P0-010
9. TC-P0-011
10. TC-REG-001

如果改动涉及调度、原生弹框、字段映射、运行结果区，则必须额外补测相关 P1 / 异常 / 原生回归用例。

## 12. 交付时必须反馈的测试结论

每次交付时，最终说明中必须写清：

- 本轮改动影响哪些页面、接口、路由和数据流
- 实际执行了哪些测试用例编号
- 哪些用例通过
- 哪些用例未测及原因
- 是否执行了原生功能保护回归
- 若发现问题，问题已如何修复并复测

## 13. 后续维护方式

后续如果你新增需求，不仅要改需求文档，也建议同步改本文档中的测试用例。

原则是：

- 新增一个功能点，就新增对应测试点
- 修复一个历史 bug，就沉淀对应回归用例
- 发现一个高频问题，就把它写成必测项

这样我后面每次开发，都能明确知道“这次必须测什么”，而不是临时拼测试路径。
