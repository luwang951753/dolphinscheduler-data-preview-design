# 数据预览页面原型说明文档

## 1. 文档定位

本文档定义“数据预览”页面的最终原型方向、布局结构、交互细节和视觉原则。当前版本以 DataGrip Data Editor 为核心参考，目标是做一个专业的数据表查看器，而不是 BI 报表页。

本文档用于指导：

- HTML 原型设计。
- 后续 Vue 页面开发。
- 交互验收。
- 真人点击测试。

## 2. 页面设计基准

### 2.1 核心参考

页面必须参考 DataGrip Data Editor 的结构：

- 左侧数据库对象树。
- 中间表格数据网格。
- 顶部紧凑工具栏。
- WHERE / ORDER BY 条件贴近表格。
- 表头提供筛选和排序入口。
- 底部状态栏展示行数、耗时、分页。

### 2.2 设计禁止项

页面不允许设计为：

- BI 图表工作台。
- 仪表盘页面。
- 大卡片式数据概览。
- 营销式 Hero 页面。
- 左侧复杂表单 + 右侧小表格。

## 3. 页面路由与入口

建议路由：

- `/ui/data-preview`

建议菜单名称：

- 数据预览

入口建议放在源中心、同步任务等数据相关入口附近，不能干扰 DolphinScheduler 原生工作流菜单。

## 4. 总体布局

### 4.1 页面骨架

页面采用全屏工作台布局：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶部工具栏：数据预览 / 数据源 / 数据库 / 表名与注释 / 查询 / 导出 / 保存 │
├───────────────┬────────────────────────────────────────────────────┤
│ 左侧对象树     │ 表标签栏                                             │
│ 数据源         ├────────────────────────────────────────────────────┤
│ 数据库         │ 表工具条                                             │
│ 表 / 视图       ├────────────────────────────────────────────────────┤
│ 最近打开 / 收藏 │ WHERE 条件条                                         │
│               │ ORDER BY 条件条                                      │
│               ├────────────────────────────────────────────────────┤
│               │ 数据网格                                             │
│               ├────────────────────────────────────────────────────┤
│               │ 状态栏 / 分页                                        │
└───────────────┴────────────────────────────────────────────────────┘
```

### 4.2 尺寸建议

- 页面高度：占满浏览器可视区。
- 顶部工具栏：52px。
- 左侧对象树：默认 286px，最小 220px，最大 420px，可拖拽。
- 表标签栏：36px。
- 表操作工具条：42px。
- WHERE / ORDER BY 条件区：每行 36px，超过两行折叠。
- 数据网格：占剩余全部空间。
- 底部状态栏：38px。

### 4.3 视觉密度

- 页面应使用专业工具型密度。
- 字号以 12px / 13px / 14px 为主。
- 表格行高建议 34px。
- 不使用大圆角卡片。
- 不使用大面积渐变背景。
- 分隔线、表头底色、状态标签应克制。

## 5. 顶部工具栏

### 5.1 内容布局

从左到右：

1. 页面标题：数据预览。
2. 数据源选择器。
3. 数据库选择器。
4. 表上下文显示：`▦ ajxx_tab（案件信息表）`，不额外展示 `当前表` 静态标签。
5. 执行查询按钮。
6. 刷新按钮。
7. 导出按钮。
8. 保存视图按钮。
9. 更多按钮。

### 5.2 交互

- 数据源选择器切换后，左侧对象树刷新。
- 数据库选择器切换后，对象树定位到当前库。
- 数据源选择器和数据库选择器必须是真实可选的下拉控件。
- 数据库选择器必须随数据源级联变化。
- 切换后顶部当前表、左侧对象树、底部路径状态同步更新。
- 原型中需要提供多个数据源和多个数据库选项，便于体验 N 个源、N 个库的使用场景。
- 当前表只展示上下文，不做大标题。
- 查询按钮使用主色，其他按钮低权重。
- 刷新保留当前条件。
- 导出打开导出设置弹层。
- 保存视图打开保存视图弹层。

## 6. 左侧数据库对象树

### 6.1 区域组成

左侧从上到下：

1. 对象搜索框。
2. 最近打开。
3. 数据源树。
4. 底部状态：已加载表数量 / 刷新按钮。

最近打开区：

- 展示最近打开的 1-3 张表。
- 每条记录使用表格图标 + 表名。
- 当前表高亮。
- 点击记录应打开 / 切换到对应表标签，并刷新右侧数据网格。
- 无最近记录时只展示“暂无打开表”弱提示，不展示不可点击的假入口。

### 6.2 树节点视觉

节点应表达数据库层级：

- 数据源：数据库图标 + 名称。
- 数据库 / Schema：文件夹图标 + 名称。
- 表：表格图标 + 表名。
- 视图：视图图标 + 名称。
- 当前表：浅蓝背景高亮 + 左侧强调线。
- 收藏表：星标。

对象树密度：

- 参考 DataGrip / DBeaver 的对象树，默认采用 24-28px 单行节点。
- 表节点优先显示表名，注释通过 title 或轻量辅助信息承载，不在树里强制换成两行。
- 展开箭头、对象图标、名称、数量 / 类型标识在同一行内完成。
- 层级缩进约为 14px，不能过大，否则表名区域会被挤压。
- hover 只使用轻量底色，选中使用浅蓝背景 + 左侧 2px 强调线。
- 参考 Navicat 的数据库对象导航区，图标必须表达对象语义：
  - 数据源连接节点展示数据库类型识别，例如 `MySQL` / `PG`。
  - 数据库节点使用数据库圆柱图标。
  - 表分组和表节点使用表格 / 表集合图标。
  - 视图分组使用视图图标。
  - 不使用无意义小圆点或方块作为主图标。

### 6.3 操作

- 单击表：打开表。
- 双击表：打开并执行查询。
- 节点右侧更多：复制表名、查看字段、收藏、刷新。
- 搜索框支持表名和表注释搜索。
- 对象树可折叠为窄栏。
- 数据源、数据库 / Schema、表分组均可展开 / 收起。
- 左侧对象树侧栏右边线支持左右拖拽调整宽度。
- 拖到很窄时自然进入窄栏状态，右侧数据网格自动扩展。
- 从窄栏向右拖拽可恢复宽栏，不使用突兀的顶部折叠按钮作为主入口。

嵌入 Dolphin 主框架时：

- 数据预览工作台顶部必须位于 Dolphin 顶部菜单下方。
- 页面不使用负边距硬撑满内容区，避免被 Dolphin 内容滚动容器从上下左右裁切。
- `/data-preview` 使用无内容 padding 的工作台容器，页面边界与 Dolphin 内容区自然贴合。
- 顶部工具栏、左侧搜索框和表标签栏首行必须完整可见。
- 底部状态栏也必须完整可见，不能被内容容器底部裁切。

## 7. 表标签栏

### 7.1 内容

当前至少展示一个表标签：

- 表名。
- 表注释。
- 数据库名。
- 关闭按钮。

示例：

- `ajxx_tab 案件信息表 · ds_demo`

### 7.2 交互

- 当前标签高亮。
- 多表打开时横向排列。
- 关闭当前标签后回到最近打开或空状态。

## 8. 表操作工具条

### 8.1 内容

工具条紧贴表格上方，包含：

- 重新加载。
- 列设置。
- 筛选。
- 排序。
- 关联。
- 复制 SQL。
- 每页条数。

主操作顺序固定为：列设置、筛选、排序、关联、复制 SQL。

### 8.2 交互

- 列设置打开右侧抽屉。
- 添加筛选打开条件编辑浮层。
- 添加排序打开排序字段浮层。
- 关联打开右侧抽屉。
- 每页条数切换后自动重新查询。

## 9. WHERE 条件条

### 9.1 展示

WHERE 条显示在表工具条下方，形式接近 SQL 条件：

```text
WHERE  status = '有效'   AND create_time >= '2026-05-01'   + 条件
```

### 9.2 条件 Chip

每个条件 chip 包含：

- 字段名。
- 操作符。
- 值。
- 编辑按钮。
- 删除按钮。

### 9.3 空状态

无筛选时显示：

- `WHERE  无筛选条件  + 条件`

### 9.4 高级交互

- 点击 chip 可编辑。
- 点击删除立即移除并重新查询，或等待用户点查询，具体由实现配置决定。
- 右键单元格生成的条件要自动插入 WHERE 条。
- `+ 筛选` 与 `+ 条件` 打开筛选编辑浮层。
- 筛选编辑浮层包含字段、操作符、值、应用、取消。
- 表头“按此列筛选”会预填字段。
- 无筛选时显示“无筛选条件”。

## 10. ORDER BY 条件条

### 10.1 展示

ORDER BY 条紧贴 WHERE 条：

```text
ORDER BY  create_time DESC  1   id ASC  2   + 排序
```

### 10.2 规则

- 表头排序后同步更新 ORDER BY 条。
- 多字段排序显示顺序编号。
- 清空排序后恢复默认顺序。
- `+ 排序` 打开排序管理浮层。
- 排序管理浮层支持新增多个排序项、选择字段、选择升序 / 降序、删除排序项。
- 无排序时显示“无排序条件”。

## 11. 数据网格

### 11.1 表格结构

数据网格包含：

- 行号列。
- 数据列。
- 固定表头。
- 横向滚动条。
- 纵向滚动条。

### 11.2 表头

表头展示：

- 字段名。
- 字段注释短文本。
- 排序图标。
- 过滤图标。
- 表头菜单按钮。

表头规则：

- 不在表头直接展示字段类型。
- 字段名是主信息。
- 字段注释是辅助信息，展示在字段名旁边。
- 字段注释过长时必须单行省略，使用 `...` 替代后续内容。
- 表头悬浮提示展示完整字段注释和字段类型。
- 排序、筛选、菜单入口必须固定在表头右侧，不被长注释挤出。
- 筛选 / 搜索图标必须始终可点击。
- 未筛选字段点击筛选 / 搜索图标时，直接打开筛选浮层并预填当前字段。
- 已筛选字段点击筛选 / 搜索图标时，打开当前字段已有筛选条件进行编辑。

表头菜单包含：

- 升序。
- 降序。
- 清空排序。
- 按此列筛选。
- 隐藏此列。
- 固定到左侧。
- 复制字段名。

### 11.3 单元格

单元格交互：

- 单击选中。
- 双击查看完整内容。
- 右键打开菜单。
- 长文本省略。
- NULL 使用灰色标签。
- 数字右对齐。
- 时间字段统一格式。

右键菜单包含：

- 复制值。
- 复制整行。
- 仅看此值。
- 排除此值。
- 查看完整内容。
- 按此列升序。
- 按此列降序。

## 12. 右侧抽屉

### 12.1 列设置抽屉

列设置抽屉包含：

- 字段搜索。
- 全选。
- 反选。
- 清空。
- 恢复默认。
- 字段列表。
- 字段拖拽排序。
- 固定列开关。

字段项展示：

- 勾选框。
- 字段名。
- 字段注释短文本。
- 轻量字段类型标签。
- 字段注释信息图标。
- 主键标记。
- 拖拽手柄。

列设置字段项视觉规则：

- 字段项采用单行紧凑布局，不默认展示第二行注释。
- 行高控制在 32px - 36px，提升一屏字段可见数量。
- 字段名是主信息，单行省略。
- 字段注释作为字段名后的弱信息常驻展示，单行省略。
- 字段类型是右侧弱标签，不参与主视觉。
- 字段注释通过 `i` 信息图标或悬浮 tooltip 展示完整内容。
- 长注释不允许撑开字段项高度。
- 字段列表不做卡片堆叠，避免抽屉显得笨重。

字段拖拽排序要求：

- 字段项应使用上下拖拽调整顺序。
- 拖拽手柄建议放在字段项最左侧，避免误触勾选框。
- 拖拽时字段项出现半透明状态。
- 可放置位置出现清晰边框或背景提示。
- 放开鼠标后，右侧列设置顺序立即更新。
- 中间数据网格列顺序立即按新字段顺序重排。
- 隐藏字段仍保留在排序队列中，重新勾选后按拖拽后的顺序显示。
- 原型中应能直接体验该交互。

### 12.2 关联抽屉

关联抽屉包含：

- 当前主表。
- 添加关联表。
- 主表字段。
- 关联表字段。
- 关联类型。
- 是否展示关联字段。
- 保存关联。

关联抽屉交互：

- 点击工具条 `关联` 打开右侧抽屉，抽屉标题显示“关联表”。
- 抽屉顶部展示当前主表，例如 `ajxx_tab（案件信息表）`。
- 抽屉顶部提供关联方式切换：手动关联、Lookup 关联。
- 系统默认选中手动关联。
- 关联配置采用从上到下的紧凑表单：关联表、主表字段、关联表字段、关联类型。
- 手动关联模式支持多条关联配置，每条配置独立展示为一张紧凑配置块。
- 手动关联中的 `添加另一张关联表` 必须可点击并新增配置块。
- 每条手动关联配置提供明确的删除动作，不使用无交互的“启用”“新增表”标签。
- Lookup 模式使用“关联记录字段 -> 目标表 -> 查回字段”的流程，弱化 SQL JOIN 文案。
- 关联表字段展示区使用复选框，用户只勾选想显示在结果表中的字段。
- 点击“应用关联”后，中间数据网格立即追加关联字段列。
- 追加列标题格式为 `dept_dict.dept_code`，字段注释仍作为表头辅助信息展示。
- 抽屉中应展示当前关联摘要，例如 `LEFT JOIN dept_dict ON owner_dept = dept_name`。
- 提供“清除关联”入口，清除后移除关联字段列。
- 原型阶段使用前端模拟数据即可，重点验证交互是否合理方便。

关联应用后的反馈：

- 顶部摘要出现 `1 关联`。
- WHERE / ORDER BY 上方或下方出现轻量 JOIN 摘要条。
- 新增关联字段列应自动插入到主表关键字段后方，避免用户必须横向滚动到最右侧才看到效果。
- 新增关联字段列可用浅色表头或短暂高亮提示。

### 12.3 单元格详情抽屉

用于查看长文本、JSON、时间等完整内容。

## 13. 底部状态栏

### 13.1 左侧状态

显示：

- 当前返回 50 行。
- 总计 1,284 行。
- 查询耗时 0.38s。
- 上次刷新时间 14:32:08。

### 13.2 右侧分页

显示：

- 每页条数。
- 当前页。
- 上一页。
- 下一页。
- 跳页。

## 14. 关键状态

### 14.1 初始状态

未打开表时，中间区域展示一个轻量空网格，不使用大插画：

- 文案：从左侧对象树选择一张表查看数据。
- 最近打开表快捷入口。

### 14.2 加载状态

- 保留表头和条件条。
- 网格上方显示细进度条或局部 loading。

### 14.3 无数据状态

- 网格区域显示“无匹配数据”。
- 提供清空 WHERE 条件按钮。

### 14.4 错误状态

- 错误显示在网格顶部。
- 保留当前条件。
- 提供重试。
- 错误文案要说明可修复方向。

## 15. 原型页面要求

HTML 原型文件：

- `.ai/data-preview/prototype/data-preview-prototype.html`

原型必须能直接用浏览器打开，并且必须能体验基础交互，不允许只是静态页面。原型要展示并支持：

- 左侧对象树。
- 顶部工具栏。
- 表标签栏。
- WHERE 条件条。
- ORDER BY 条件条。
- 表头筛选排序入口。
- 数据网格。
- 单元格选中态。
- 底部状态栏。
- 列设置抽屉示意。
- 左侧表节点点击切换高亮。
- 查询、刷新、分页、表头排序、表头筛选、右键筛选、条件删除、列显隐等交互。

## 16. 验收检查

页面设计验收时重点看：

1. 是否像专业 Data Editor，而不是 BI 报表。
2. 数据网格是否占据主视觉。
3. 左侧对象树是否清晰。
4. WHERE / ORDER BY 是否贴近表格且状态清楚。
5. 表头是否有筛选排序入口。
6. 单元格是否有专业数据查看交互暗示。
7. 是否没有大卡片、大渐变、大段说明。
8. 是否适合后续接入真实接口开发。

## 16.1 首期真实页面降级规则

首期真实页面应保持专业 Data Editor 布局，但未接入的能力必须降级展示：

- 路由入口与 `同步任务` 平级，菜单文案为 `数据预览`，路由为 `/data-preview`。
- `列设置` 可先只控制当前前端列显隐，不保存。
- `筛选` 和表头筛选必须真实请求后端。
- `排序` 和表头排序必须真实请求后端。
- `关联`、`复制 SQL`、`保存视图` 可先禁用或显示“后续版本支持”。
- 页面空态必须提示先选择数据源、数据库和表。

## 16.2 首期真实结果状态

真实页面的结果区状态栏需要像 DataGrip / DBeaver 一样给用户明确反馈：

- 左侧展示当前页返回行数，例如 `当前页 50 行`。
- 同时展示当前页码与每页条数，例如 `第 2 页 / 每页 50 行`。
- 最近一次查询成功后展示执行时间与耗时，例如 `2026-05-12 16:30:12 / 23 ms`。
- 后端返回行数小于每页条数时，在状态栏展示“已到末页”。
- 查询失败时在表格上方展示错误提示条，表格区域进入空结果状态。
- 查询返回 0 行时展示“当前条件无数据”，但不清空筛选、排序和 SQL 预览。

## 16.3 真实页面工具条与抽屉

真实 Vue 页面必须和已确认 HTML 原型保持一致：

- 列设置、筛选、排序、关联、复制 SQL 放在表格上方工具条。
- 工具条按钮顺序为：列设置、筛选、排序、关联、复制 SQL。
- 列设置不允许常驻固定在右侧，必须点击“列设置”后打开右侧抽屉。
- 筛选、排序、关联也必须按需打开抽屉或浮层，关闭后表格恢复完整宽度。
- 复制 SQL 是工具条动作，可直接复制当前结构化 SQL；如展示 SQL 预览，也应通过按需面板呈现。
- 右侧抽屉必须可关闭，关闭后不丢失已配置的字段显隐、筛选和排序。

## 17. 个人视图管理交互

入口放在表格操作工具条最左侧，位于 `列设置` 前：

```text
视图：默认视图 ▼  列设置  筛选  排序  关联  复制SQL
```

下拉内容：

```text
我的视图
✓ 默认视图
  同步结果排查
  只看有效案件
  最近30天创建
────────
保存当前视图
另存为新视图
重命名当前视图
删除当前视图
```

交互规则：

- 当前视图使用勾选标记。
- 有未保存修改时，入口显示 `视图：默认视图 *`。
- 切换视图时如存在未保存修改，弹确认框。
- 另存和重命名使用小型输入弹窗。
- 删除普通视图前二次确认。
- 默认视图的重命名、删除入口置灰或点击时提示原因。

### 17.1 个人视图持久化交互

真实 Vue 页面从本轮开始必须接入后端个人视图接口，不再只做前端内存模拟。

加载规则：

- 打开一张表后，先根据字段元数据生成 `默认视图`。
- 随后调用 `GET /datasources/preview-views` 拉取当前用户在该表下保存过的普通个人视图。
- 视图下拉中默认视图始终排第一，后端视图按更新时间倒序展示。
- 如果后端视图加载失败，页面保留默认视图并允许继续查数，同时给出轻量错误提示。

保存规则：

- 点击 `保存当前视图`：
  - 当前为普通后端视图时，调用更新接口覆盖该视图配置。
  - 当前为默认视图时，提示用户输入名称并调用新增接口，相当于另存为新视图。
- 点击 `另存为新视图`：输入名称后调用新增接口，成功后新视图自动选中。
- 删除普通视图：调用删除接口，成功后从列表移除并切回默认视图。
- 视图保存成功后，入口上的 `*` 未保存标识消失。

反馈规则：

- 保存、另存、删除期间对应菜单项进入 loading 或禁用状态，避免重复提交。
- 重名、名称为空、名称过长时展示明确提示。
- 接口失败时不清空当前页面配置，用户可以修改后重试。
