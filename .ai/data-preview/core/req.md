# 数据预览模块需求开发文档

## 1. 文档定位

本文档用于定义 DolphinScheduler 二开中“数据预览”模块的产品需求、交互边界、页面能力、后端能力和验收标准。

从 2026-05-12 起，数据预览模块的产品形态明确调整为“专业数据表查看器 / Data Editor”，重点参考 JetBrains DataGrip Data Editor、DBeaver Data Editor、云厂商 DMS 表数据查看页，而不是 BI 报表、图表分析或仪表盘。

后续所有数据预览开发必须先更新本文档，再更新页面原型说明和测试用例，最后进入代码开发与真人点击测试。

## 2. 产品定位

### 2.1 是什么

数据预览是一个面向数据开发、后端开发、平台运维和业务支持人员的专业表数据查看页面。用户可以在 DolphinScheduler 内完成以下动作：

1. 从数据源、库、表对象树中快速打开表。
2. 以数据网格方式查看表数据。
3. 使用贴近表格的 WHERE 条件过滤数据。
4. 使用贴近表格的 ORDER BY 条件排序数据。
5. 通过表头入口完成列筛选、排序、隐藏和列宽调整。
6. 通过单元格右键快速复制、仅看此值、排除此值。
7. 保存当前表格视图，复用字段显隐、筛选、排序和分页配置。

### 2.2 不是什么

本模块不是：

- BI 报表平台。
- 图表分析工具。
- 大屏或仪表盘设计器。
- 复杂 SQL IDE。
- 数据建模或语义层产品。

页面不应出现柱状图、饼图、指标大屏、营销式 Hero、复杂图表配置区。页面的专业感来自数据库对象树、查询条件条、数据网格、状态栏和高密度表格操作。

## 3. 参考产品与设计依据

### 3.1 核心参考

首要参考 DataGrip Data Editor：

- 左侧数据库对象树，用于定位数据源、库、表。
- 中间数据表格为主体，表头支持排序和过滤。
- 表格上方提供工具栏、WHERE 条件、ORDER BY 条件。
- 表格底部提供分页、执行耗时、行数和状态反馈。
- 单元格支持复制、过滤、查看完整值等快捷操作。

### 3.2 辅助参考

辅助参考 DBeaver Data Editor 与云厂商 DMS：

- DBeaver 的数据网格、结果过滤、行编辑和状态栏。
- 阿里云 DMS / 腾讯云 DMC / 华为云 DataArts Studio 的数据源树、表数据预览、权限提示和导出能力。
- Airtable / Baserow 的视图保存、字段隐藏、字段排序和筛选配置体验，但不采用其低代码协作表格风格。

### 3.3 设计取舍

本模块应学习 DataGrip / DBeaver 的数据查看效率，但必须适合 Web 管理平台：

- 不做桌面 IDE 级菜单复杂度。
- 不要求用户写完整 SQL。
- WHERE / ORDER BY 采用可视化条件条，可展示类 SQL 文案。
- 高级能力通过弹层或抽屉打开，不常驻挤压数据表。

## 3.4 首期真实二开范围

首期真实二开只交付数据预览的最小可用闭环：

- 接入 DolphinScheduler 真实路由 `/data-preview`。
- 在 DolphinScheduler 菜单中新增与 `同步任务` 平级的一级入口 `数据预览`。
- 复用源中心已有数据源权限与数据源列表。
- 支持选择数据源、数据库和表。
- 支持读取真实字段元数据。
- 支持只读查询第一页数据。
- 支持基础筛选和排序。
- 查询请求必须使用结构化参数，不允许前端传入任意 SQL。
- 后端必须限制 pageSize，默认 50，最大 200。
- 后端必须校验表名、字段名和排序字段来自元数据白名单。

首期已先完成真实数据预览闭环，个人视图此前仅为前端内存模拟，不作为生产可用能力。

### 3.4.2 本轮真实二开范围：个人视图持久化

从 2026-05-12 本轮迭代开始，数据预览需要补齐个人视图持久化，使“保存视图”从可体验交互升级为真实后端能力。

本轮交付范围：

- 新增数据预览个人视图后端表，按用户、数据源、数据库、schema、表保存。
- 提供个人视图列表、新增、更新、删除接口。
- 默认视图仍由前端根据当前字段元数据生成，不写入数据库。
- 普通个人视图保存字段显隐、字段顺序、WHERE、ORDER BY、分页大小和关联配置。
- 切换数据源、数据库或表后，应重新加载该表对应的个人视图列表。
- 视图接口必须复用 DolphinScheduler 登录态和数据源权限校验，用户只能管理自己有权限数据源下自己的视图。
- 同一用户、同一数据源、同一数据库、同一 schema、同一表下，普通视图名称不能重复。
- 删除当前普通视图后自动回到默认视图，并保留当前表可继续查询。

本轮不交付：

- 共享视图。
- 团队视图。
- 视图权限授权。
- 任意 SQL 编辑器。
- 将查询结果快照保存到数据库。

### 3.4.1 首期真实闭环补充要求

真实页面不能只把表格渲染出来，还必须把一次查询的执行状态表达完整：

- 查询结果区必须展示当前页返回行数、当前页码、每页条数、执行耗时和执行时间。
- 后端返回的 `rowCount`、`pageNo`、`pageSize`、`elapsedMs`、`executedAt` 必须被前端消费，不能只消费 `rows`。
- 翻页采用“上一页 / 下一页”轻量模式，不做总数统计，避免对大表额外执行 `COUNT(*)`。
- 当返回行数小于每页条数时，应明确提示“当前页已是末页”或禁用下一页。
- 查询失败时，表格区域必须有可见错误状态，不能只依赖全局 toast。
- 空结果时应展示“当前条件无数据”，并保留 WHERE / ORDER BY / SQL 预览，方便用户调整条件。
- 重新加载当前表时保留字段显隐、列顺序、筛选、排序和每页条数。
- 预览结果应尽量保持中文可读；对于 MySQL 历史数据中常见的 UTF-8 被 Latin-1 / Windows-1252 误解码文本，后端可做保守纠正，但只有纠正结果明显包含中文时才替换原值。
- 列设置、筛选、排序、关联不能作为右侧常驻大栏挤压表格；应通过表格上方工具条触发右侧可关闭抽屉。
- 工具条按钮顺序固定为：列设置、筛选、排序、关联、复制 SQL。

## 4. 用户与场景

### 4.1 主要用户

- 数据开发工程师：查看同步结果、排查数据问题。
- 后端开发工程师：联调接口时核对库表内容。
- 平台运维人员：确认数据源连通性、权限和表结构。
- 业务支持人员：按条件查看业务数据，不手写 SQL。

### 4.2 高频场景

1. 打开某个数据源下的库表，查看前 50 条数据。
2. 按状态、日期、编号快速过滤。
3. 点击表头按时间倒序查看最新数据。
4. 右键某个单元格，仅查看同值记录。
5. 隐藏暂时不关心的字段，保留关键列。
6. 调整列宽、列顺序，保存为个人视图。
7. 导出当前筛选结果。
8. 查看 NULL、长文本、时间、数字字段是否正确。

## 5. 总体信息架构

页面路由建议：

- `/ui/data-preview`

页面采用 Data Editor 结构：

1. 顶部全局工具栏。
2. 左侧数据库对象树。
3. 中间数据编辑器工作区。
4. 数据网格上方的 WHERE / ORDER BY 条件条。
5. 数据网格主体。
6. 底部状态栏和分页区。
7. 右侧按需打开的详情抽屉，不默认常驻。

## 6. 顶部全局工具栏需求

### 6.1 内容

顶部工具栏用于表达当前上下文和全局动作，应包含：

- 页面标题：数据预览。
- 数据源选择器。
- 数据库选择器。
- 当前打开表名与表注释。
- 当前打开表上下文应直接展示表名与表注释，不额外展示 `当前表` 等低信息量静态标签。
- 刷新按钮。
- 执行查询按钮。
- 导出按钮。
- 保存视图按钮。
- 更多操作入口。

### 6.2 交互要求

- 切换数据源后刷新左侧对象树。
- 切换数据库后对象树定位到当前库。
- 数据源和数据库必须是可选控件，不能写死为单一数据源或单一数据库。
- 一个用户可能有 N 个数据源，每个数据源下可能有 N 个数据库 / Schema。
- 数据源与数据库必须级联：切换数据源后，数据库选项更新为该数据源下的库列表。
- 切换数据源后，应优先选中该数据源连接配置中的默认数据库；只有默认数据库不存在于返回库列表时，才回退到数据库列表第一项。
- 切换数据源或数据库后，当前对象树、最近打开表、当前表上下文和状态栏路径必须同步更新。
- 如果新数据源 / 数据库下没有当前表，应清空当前表或自动打开默认表，并给出明确状态。
- 打开表后顶部显示 `表名（表注释）`，无注释时只显示表名。
- 点击执行查询时，按当前 WHERE / ORDER BY / 字段配置 / 分页参数重新查询。
- 刷新只刷新当前表数据，不重置字段、筛选和排序。
- 保存视图保存当前用户的表格状态。

### 6.3 视觉要求

- 工具栏高度控制在 48-56px。
- 不使用大卡片，不使用大段说明文案。
- 主按钮只有一个：执行查询。
- 其他操作采用图标按钮或低权重按钮。

## 7. 左侧数据库对象树需求

### 7.1 目标

帮助用户像在 DataGrip 中一样从数据源、库、Schema、表快速定位数据对象。

### 7.2 树结构

对象树层级建议：

1. 数据源。
2. 数据库 / Schema。
3. 表分组。
4. 表。
5. 字段预览节点，可选。

示例：

- mysql_case_workbench
  - ds_demo
    - 表
      - ajxx_tab 案件信息表
      - user_info 用户信息表
    - 视图
      - v_case_summary

### 7.3 功能要求

- 支持搜索表名和表注释。
- 支持展开 / 收起节点。
- 支持刷新对象树。
- 支持整个左侧对象树侧栏折叠 / 展开。
- 支持最近打开表快捷区。
- 最近打开表快捷区必须可点击，不应只是静态提示文本；点击后应打开 / 切换对应表标签，并加载该表数据。
- 最近打开为空时展示弱提示；已有记录时最多展示 3-5 条，避免挤占对象树主体高度。
- 支持收藏表。
- 当前打开表需要高亮。
- 表节点应展示表名，辅助展示表注释。
- 表数量较多时必须虚拟滚动或分页加载。
- 对象树应参考 DataGrip Database Explorer、DBeaver Database Navigator、pgAdmin Object Explorer 的专业密度：
  - 节点默认使用单行紧凑展示，不应把每张表做成松散的两行卡片。
  - 数据源、数据库 / Schema、表分组、表节点的缩进层级必须清晰。
  - 每个可展开节点左侧必须有稳定的展开 / 收起箭头。
  - 分组节点右侧可展示子节点数量，例如 `3`。
  - 表节点右侧可展示轻量类型标识，例如 `TABLE`，但不得喧宾夺主。
  - 当前表使用浅蓝背景和左侧强调线高亮。
- 对象树图标应参考 Navicat Navigation Pane：
  - 连接 / 数据源节点必须能体现数据库类型，例如 MySQL、PostgreSQL。
  - 不允许使用无业务含义的小圆点、小方块作为主要对象图标。
  - 数据库 / Schema 节点使用数据库语义图标。
  - 表节点使用表格网格语义图标。
  - 视图节点使用区别于表的视图语义图标。
  - 图标只用于识别对象类型，不应抢占表名展示空间。

### 7.4 交互要求

- 单击表节点打开数据表。
- 打开表后自动加载字段元数据和第一页数据。
- 表节点右键或更多菜单支持：打开表、复制表名、查看字段、收藏。
- 对象树宽度默认 280px，可拖拽调整，可折叠到窄栏。

展开与折叠要求：

- 数据源节点、数据库 / Schema 节点、表分组节点必须支持展开 / 收起。
- 收起父节点后，子节点应隐藏，但不丢失当前选择状态。
- 左侧对象树侧栏不应使用突兀的固定折叠按钮作为主交互。
- 侧栏右边界应支持左右拖拽调整宽度。
- 拖拽到较窄阈值时，侧栏自然进入窄栏状态，仅保留最小对象树入口。
- 从窄栏向右拖拽应恢复正常宽度。
- 调整宽度后，中间数据网格应自动占满剩余宽度。
- 展开 / 收起侧栏不应丢失之前的对象树展开状态。

页面嵌入 Dolphin 主框架时的布局要求：

- 数据预览页面可以使用贴边工作台布局，但不得使用会伸入顶部主菜单区域的负边距。
- 数据预览页面不得依赖负边距撑满 Dolphin 内容容器，避免被 `NLayoutContent` / 滚动容器裁切出“方框遮挡”效果。
- `/data-preview` 路由应使用无内容 padding 的工作台容器，避免专业数据编辑器界面被包在默认表单页留白框中。
- 页面顶部工具栏必须完整显示在 Dolphin 顶部菜单下方，不能被主菜单遮挡。
- 页面高度应优先使用 Dolphin 内容容器的可用高度自适应，避免底部状态栏、顶部工具栏、左侧对象树被父容器裁切。

## 8. 数据编辑器工作区需求

### 8.1 工作区结构

中间工作区从上到下包含：

1. 当前表标签栏。
2. 表操作工具条。
3. WHERE 条件条。
4. ORDER BY 条件条。
5. 数据网格。
6. 分页与状态栏。

### 8.2 表标签栏

支持多个已打开表标签，但本期可先实现单标签视觉：

- 标签显示表名和表注释。
- 标签显示数据源和库的辅助信息。
- 标签可关闭。
- 当前标签高亮。

### 8.3 表操作工具条

应包含：

- 重新加载。
- 列设置。
- 筛选。
- 排序。
- 关联。
- 复制 SQL。
- 每页条数选择。

主操作按钮必须按以下顺序展示：

1. 列设置
2. 筛选
3. 排序
4. 关联
5. 复制 SQL

工具条必须贴近数据网格，不能放成远离表格的大模块。

## 9. WHERE 条件条需求

### 9.1 目标

提供贴近 SQL 但不要求手写 SQL 的筛选体验，让用户清楚知道当前结果为什么被过滤。

### 9.2 展示形式

WHERE 条件条位于表格上方，展示为一行或多行条件 chip：

- `WHERE status = '有效'`
- `AND create_time >= '2026-05-01'`
- `AND city IS NOT NULL`

每个条件 chip 应包含：

- 字段名。
- 操作符。
- 条件值。
- 删除按钮。
- 编辑入口。

### 9.3 新增筛选

新增筛选入口包括：

- 条件条中的 `+ 条件`。
- 表头过滤图标。
- 单元格右键 `仅看此值`。
- 单元格右键 `排除此值`。

### 9.4 筛选类型

按字段类型提供操作符：

文本字段：

- 等于。
- 不等于。
- 包含。
- 不包含。
- 开头是。
- 结尾是。
- 为空。
- 不为空。
- 在列表中。

数值字段：

- 等于。
- 不等于。
- 大于。
- 大于等于。
- 小于。
- 小于等于。
- 区间。
- 为空。
- 不为空。

日期时间字段：

- 今天。
- 昨天。
- 最近 7 天。
- 最近 30 天。
- 本月。
- 上月。
- 自定义时间范围。
- 为空。
- 不为空。

布尔字段：

- 是。
- 否。
- 为空。
- 不为空。

### 9.5 组合规则

- 本期必须支持多个条件 AND。
- 条件顺序按添加顺序展示。
- 后续可扩展 OR 分组，但不作为首期必须项。
- 条件过多时折行展示，最多占用两行，超过后收进“更多条件”。

### 9.6 筛选编辑交互

筛选功能必须具备完整编辑能力，不能只追加固定示例条件。

要求：

- 点击 `+ 筛选` 或 `+ 条件` 打开筛选编辑浮层。
- 点击已有 WHERE 条件 chip 可打开同一浮层编辑该条件。
- 表头菜单中的“按此列筛选”应带入当前字段打开筛选浮层。
- 筛选浮层包含字段、操作符、值三个核心控件。
- 操作符应根据字段类型给出合理选项。
- 点击应用后更新 WHERE 条件条和结果表状态。
- 点击删除按钮可移除单个条件。
- 点击清空筛选可移除全部条件。
- 无筛选时 WHERE 条应显示“无筛选条件”，而不是空白。

## 10. ORDER BY 条件条需求

### 10.1 目标

让排序状态像 SQL ORDER BY 一样清楚可见，同时支持表头快捷操作。

### 10.2 展示形式

ORDER BY 条件条位于 WHERE 下方或与 WHERE 合并为查询条件区。展示示例：

- `ORDER BY create_time DESC, id ASC`

每个排序 chip 应包含：

- 字段名。
- 升序 / 降序。
- 优先级。
- 删除按钮。

### 10.3 交互入口

排序入口包括：

- 点击表头排序。
- 表头菜单选择升序 / 降序 / 清空排序。
- 条件条中 `+ 排序`。

### 10.4 排序规则

- 单击表头：升序。
- 再次单击：降序。
- 第三次单击：清空该字段排序。
- 多字段排序需要显示排序优先级。
- 当前排序字段表头必须有明确图标。

### 10.5 排序管理交互

排序功能必须支持完整管理，不应只有表头单字段切换。

要求：

- 点击 `+ 排序` 打开排序管理浮层。
- 排序浮层展示当前排序字段列表。
- 每个排序项支持选择字段、选择升序 / 降序、删除。
- 支持新增排序项，形成多字段排序。
- 多字段排序应展示优先级。
- 点击应用后更新 ORDER BY 条和表头排序图标。
- 点击清空排序可移除全部排序条件。
- 无排序时 ORDER BY 条应显示“无排序条件”。

## 11. 数据网格需求

### 11.1 目标

数据网格是页面主角，必须占据页面最大面积，提供专业、稳定、高密度的数据查看体验。

### 11.2 表格基础能力

必须支持：

- 固定表头。
- 横向滚动。
- 纵向滚动。
- 行号列。
- 列宽拖拽。
- 字段显示 / 隐藏。
- 字段顺序调整。
- 单元格省略显示。
- 悬浮查看完整值。
- NULL 值特殊样式。
- 当前选中单元格高亮。
- 当前选中行轻高亮。

### 11.3 表头能力

每个表头应包含：

- 字段名。
- 字段注释短文本，作为字段名旁边的辅助信息展示。
- 字段注释 tooltip，用于查看完整注释。
- 排序状态图标。
- 过滤状态图标。
- 表头菜单入口。

表头展示规则：

- 表头不直接展示字段类型，避免压缩表格可读空间。
- 字段名是主信息，保持清晰可读。
- 字段注释是辅助信息，显示在字段名后方或下方。
- 字段注释可能很长，必须使用单行省略号截断，不允许撑宽表头或挤压排序、筛选入口。
- 字段类型只在列设置抽屉、字段详情 tooltip 或字段元数据面板中展示。
- 鼠标悬浮表头时可查看完整字段注释、字段类型、是否主键等元数据。
- 表头右侧的筛选 / 搜索图标必须是可点击入口，不能只做状态展示。
- 点击未筛选字段的筛选 / 搜索图标，应打开筛选浮层并预填当前字段。
- 点击已筛选字段的筛选 / 搜索图标，应打开该字段已有筛选条件进行编辑。

表头菜单支持：

- 升序排序。
- 降序排序。
- 清空排序。
- 按此列筛选。
- 隐藏此列。
- 固定到左侧。
- 复制字段名。

### 11.4 单元格右键菜单

单元格右键或更多操作支持：

- 复制单元格值。
- 复制整行 JSON。
- 仅看此值。
- 排除此值。
- 查看完整内容。
- 按此列升序。
- 按此列降序。

### 11.5 数据格式

数据展示要求：

- NULL 使用灰色 `NULL` 标识，不与空字符串混淆。
- 空字符串显示为 `''` 或轻量空值标识。
- 时间字段采用统一格式。
- 数字字段右对齐。
- 布尔字段显示为 true / false 或是 / 否。
- 长文本截断，支持展开查看。

### 11.6 原型交互要求

数据预览 HTML 原型必须具备可体验交互，不应只是静态截图。至少支持：

- 点击左侧对象树切换当前表高亮。
- 点击执行查询显示查询状态和刷新时间变化。
- 点击表头循环切换升序、降序、取消排序，并同步 ORDER BY 条。
- 点击表头菜单或筛选入口可生成 WHERE 条件。
- 右键单元格打开菜单，支持“仅看此值”“排除此值”并生成 WHERE 条件。
- 点击条件 chip 的删除按钮可移除条件。
- 点击列设置打开 / 关闭抽屉。
- 在列设置中勾选 / 取消字段后，数据网格对应列显示 / 隐藏。
- 在列设置中上下拖拽字段项后，数据网格列顺序必须同步变化。
- 点击分页按钮能切换页码状态。
- 单击单元格能显示选中态，双击或查看完整内容能展示完整值。

## 12. 字段列设置需求

### 12.1 入口

列设置通过工具条 `列设置` 打开抽屉或弹层，不常驻占用主表格空间。

### 12.2 功能

列设置支持：

- 搜索字段。
- 全选。
- 反选。
- 清空。
- 恢复默认。
- 拖拽调整列顺序。
- 固定列。
- 显示字段名、字段注释、字段类型、主键标识。

### 12.3 列设置视觉密度

列设置抽屉应参考 DataGrip、DBeaver、Airtable、Baserow 的字段显示面板，采用紧凑字段清单，不应把字段名、字段注释、字段类型以同等权重堆叠成多行。

默认展示规则：

- 字段项默认单行展示，目标行高控制在 32px - 36px。
- 常驻信息保留拖拽手柄、勾选框、字段名、字段注释短文本、轻量字段类型标识。
- 字段名是唯一主信息，必须单行省略。
- 字段注释必须常驻展示，但只能作为字段名后的单行弱信息，不允许单独占用第二行。
- 字段类型不能抢视觉权重，应以小号灰色标签或图标展示在右侧。
- 主键、索引等元数据可以用小图标展示，不得增加字段项高度。
- 字段注释很长时，只能在 tooltip / 浮层中完整展示，不能撑开列表行高。
- 搜索仍应支持按字段名、字段注释和字段类型匹配。

交互要求：

- 鼠标悬浮字段项时，可查看字段注释、字段类型、主键等完整元数据。
- 点击信息图标可查看完整字段注释。
- 列设置应优先保证一屏可看到更多字段，减少滚动成本。

### 12.4 字段拖拽排序

列设置中的字段项必须支持上下拖拽排序，用于让用户把最关注的字段排在前面。

交互要求：

- 字段项左侧或右侧应提供清晰的拖拽手柄。
- 鼠标悬浮字段项时应提示该项可以拖拽。
- 拖拽过程中被拖拽字段应有半透明或阴影状态。
- 拖拽到其他字段上方或下方时，应有明确的落点反馈。
- 放开鼠标后，字段列表顺序立即更新。
- 数据网格列顺序必须按字段列表的新顺序同步重排。
- 已隐藏字段也参与排序；隐藏字段重新勾选后，应出现在用户拖拽后的目标位置。
- 搜索字段时，如果只展示过滤后的字段，拖拽排序应谨慎处理；原型阶段可只支持在未搜索状态下拖拽，并给出提示。
- 恢复默认应恢复系统字段默认顺序和默认显隐状态。

### 12.5 默认规则

- 新打开表默认显示全部字段。
- 字段数量超过阈值时，可默认显示前 N 个常用字段，并提示可在列设置中恢复全部。
- 用户保存视图后，以视图配置为准。

## 13. 关联查看需求

### 13.1 定位

关联查看不是首屏主流程，不应干扰 Data Editor 主界面。

### 13.2 入口

关联能力通过工具条 `关联` 或更多菜单打开抽屉。

### 13.3 能力范围

本期建议支持：

- 主表关联一张明细表。
- 选择关联表。
- 选择主表字段。
- 选择关联表字段。
- 选择关联类型：左连接、内连接。
- 选择是否展示关联表字段。

### 13.4 展示规则

添加关联后：

- WHERE / ORDER BY 可使用关联表字段。
- 数据网格中关联表字段使用 `表名.字段名` 展示。
- 查询摘要显示已关联表数量。

### 13.5 原型交互要求

数据预览原型中的关联能力必须可体验，不应只提示“后续接入”。

原型至少支持：

- 点击工具条 `关联` 打开右侧关联抽屉。
- 提供多种关联方式供用户选择，而不是只有单一表单。
- 默认推荐一组合理关联，例如 `ajxx_tab.owner_dept = dept_dict.dept_name`。
- 支持选择关联表。
- 支持选择主表字段。
- 支持选择关联表字段。
- 支持选择关联类型：左连接、内连接。
- 支持勾选需要展示的关联表字段。
- 点击应用后，数据网格立即追加关联表字段列。
- 关联字段列标题使用 `关联表.字段名`，注释说明来自关联表字段注释。
- 状态栏或顶部摘要显示已关联表数量。
- 可清除关联，清除后移除关联字段列。
- 原型数据可使用前端模拟，不要求真实后端查询。

### 13.6 关联方式建议

参考 Metabase、DataGrip、Airtable、Baserow 等成熟产品，数据预览可提供以下关联方式：

1. 手动关联：用户选择一张或多张关联表、主表字段、关联表字段和关联类型，适合没有明确外键的库表。
2. Lookup 关联：类似 Airtable / Baserow 的 linked record + lookup，先选择主表中的“关联记录字段”，再选择要从关联表查回的字段，不强调 SQL JOIN 术语。

首期保留“手动关联 + Lookup 关联”两种方式即可。推荐关联和关系路径暂不进入主原型，避免增加用户理解成本。

手动多表关联要求：

- 支持新增多条关联配置。
- 每条配置独立选择关联表、主表字段、关联表字段、关联类型和展示字段。
- 多条关联配置应以卡片或可折叠区展示，避免混成一个大表单。
- 每条关联配置可单独删除。
- `添加另一张关联表` 必须是可用动作，点击后新增一张可配置的关联卡片。
- 不使用“启用”“新增表”等无交互标签，避免用户误解其含义。
- 应用后数据网格可同时展示多个关联表字段。
- 关联摘要应展示多条 JOIN 关系。

Lookup 交互要求：

- 第一步选择主表中的关联记录字段，例如 `owner_dept`。
- 第二步选择该字段对应的目标表，例如 `dept_dict`。
- 第三步选择要查回的字段，例如部门编码、部门负责人。
- 页面文案应避免要求用户理解 SQL JOIN。

## 14. 分页与状态栏需求

### 14.1 分页

- 上一页。
- 下一页。

### 14.2 状态信息

底部状态栏左侧展示：

- 当前返回行数。
- 总行数或估算行数。
- 查询耗时。
- 当前数据源。
- 当前库。
- 当前表。
- 上次刷新时间。

- 最大返回列数需要限制。
- 查询超时时保留条件并允许重试。
- 大表统计总数可使用估算或延迟加载。

## 20. 个人视图管理

### 20.1 目标

- 用户可以为当前数据源、数据库、schema、表保存个人视图。
- 个人视图只保存看表方式，不保存查询结果。
- 切换个人视图后，页面恢复列显隐、列顺序、列宽、筛选条件、排序条件和分页大小。
- 未保存修改必须显示 `*`，切换前需要确认，避免误丢配置。

### 20.2 保存范围

保存：

- 字段显隐。
- 字段顺序。
- 列宽。
- WHERE 筛选条件。
- ORDER BY 排序条件。
- 分页大小。
- 关联配置，包括关联模式、关联表、关联字段、关联类型和展示字段。

不保存：

- 当前页码。
- 当前查询结果。
- 当前单元格选中状态。
- 导出配置。
- 当前数据源、数据库、schema、表。

### 20.4 后端持久化要求

个人视图后端存储建议表名为 `t_ds_data_preview_view`。

字段要求：

- `id`：自增主键。
- `user_id`：当前登录用户 ID。
- `datasource_id`：数据源 ID。
- `database_name`：数据库名。
- `schema_name`：Schema 名，可为空。
- `table_name`：表名。
- `view_name`：个人视图名称。
- `view_config`：视图配置 JSON 字符串。
- `create_time`：创建时间。
- `update_time`：更新时间。

接口要求：

- `GET /datasources/preview-views`：查询当前用户在指定数据源、库、schema、表下的视图列表。
- `POST /datasources/preview-views`：新增个人视图。
- `PUT /datasources/preview-views/{id}`：更新个人视图名称或配置。
- `DELETE /datasources/preview-views/{id}`：删除个人视图。

安全与边界：

- 每个接口必须校验数据源存在且当前用户拥有数据源操作权限。
- 更新和删除时必须校验视图属于当前登录用户。
- `view_name` 去除首尾空格后不能为空，长度不超过 30。
- `view_config` 不能为空，后端至少限制最大长度，避免超大 JSON 写入元数据库。
- 重名时返回明确错误，不允许静默覆盖其他视图。
- 接口只保存配置，不执行数据查询。

### 20.3 操作规则

- 默认视图始终存在。
- 默认视图不能删除。
- 默认视图不能重命名。
- 普通个人视图可以保存、另存、重命名和删除。
- 同一张表下视图名称不能重复。
- 视图名称不能为空，最长 30 个中文字符。
- 删除普通视图后自动切回默认视图。
- 视图列表加载失败时，页面仍可使用默认视图查数。

## 21. 验收标准

### 21.1 基础验收

必须通过：

1. 可以进入 `/ui/data-preview`。
2. 可以从左侧对象树打开表。
3. 打开表后表名、表注释、字段和第一页数据正确展示。
4. WHERE 条件可新增、编辑、删除并生效。
5. ORDER BY 条件可新增、切换升降序、删除并生效。

7. 表头筛选入口可用。

9. 单元格右键 `排除此值` 可生成筛选。
10. 字段显隐和列宽调整可用。
11. 分页可用。
12. 导出遵循当前筛选和字段配置。

测试结论必须说明执行用例、通过情况、未执行原因、影响页面、接口、路由和数据流。
