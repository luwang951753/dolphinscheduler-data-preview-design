# 数据预览模块测试用例基线文档

## 1. 文档定位

本文档用于定义“数据预览”模块每次开发后必须执行的测试范围与测试用例，作为后续真实点击自测和回归测试的基线。

目标是让后续每次做数据预览开发时，都清楚知道：

- 哪些流程必须测
- 哪些基础能力必须回归
- 哪些异常必须覆盖
- 哪些原生功能必须保护

## 2. 测试总体原则

### 2.1 核心原则

- 必须采用模拟人类逐步点击页面方式测试
- 不能只跑接口
- 不能只跑构建
- 不能只验证单一 Happy Path
- 结果必须可记录、可复现

### 2.2 测试分层

每次交付前，至少分四层执行：

1. 页面主流程测试
2. 基础能力测试
3. 异常与边界测试
4. 原生功能保护测试

## 3. 测试环境基线

### 3.1 页面地址

- DolphinScheduler UI：`http://127.0.0.1:12345/dolphinscheduler/ui`
- 数据预览页面：建议为 `/ui/data-preview`

### 3.2 测试账号

- 用户名：`admin`
- 密码：`dolphinscheduler123`

### 3.3 典型数据源

建议至少准备：

- `mysql_case_workbench`
- `pgsql_test1`

### 3.4 典型测试表

建议至少准备：

- 单表数据查看用表
- 可关联的主表
- 可关联的明细表

后续正式开发时，应在本文件中补充明确的表名和字段名。

### TC-REAL-P0-005 排序查询

#### 目标

点击表头排序后 ORDER BY 条更新，重新查询后排序参数发送给后端。

### TC-REAL-P0-006 查询结果状态栏

#### 目标

真实查询后页面正确展示后端返回状态。

#### 操作步骤

1. 打开 `/data-preview`。
2. 选择可查询的数据源、数据库和表。
3. 点击“查询”。
4. 修改每页条数后再次查询。
5. 点击“下一页”，再点击“上一页”。

#### 预期结果

- 状态栏展示当前页行数。
- 状态栏展示当前页码和每页条数。
- 最近执行时间和耗时来自后端返回。
- 中文字段注释和中文单元格值应保持可读，不能出现明显的 `åˆ‘äº‹` 这类编码乱码。
- 当返回行数小于每页条数时，下一页按钮禁用或显示已到末页。
- 翻页不清空列设置、筛选、排序和 SQL 预览。

### TC-REAL-P0-006A 工具条与抽屉布局

#### 目标

验证真实页面和已确认 DataGrip 风格原型一致，不出现右侧常驻配置栏。

#### 操作步骤

1. 打开 `/data-preview`。
2. 查看表格上方工具条。
3. 依次点击“列设置”“筛选”“排序”“关联”。
4. 点击抽屉关闭按钮。
5. 点击“复制 SQL”。

#### 预期结果

- 工具条按钮顺序为：列设置、筛选、排序、关联、复制 SQL。
- 点击列设置后右侧抽屉打开，关闭后表格恢复完整宽度。
- 筛选、排序、关联均不是常驻右侧栏。
- 复制 SQL 是工具条动作，不挤占表格区域。

### TC-REAL-P0-006B 左侧对象树拖拽宽度

#### 目标

验证真实页面左侧对象树侧栏与已确认原型一致，通过右边界拖拽完成宽栏、窄栏和恢复宽栏。

#### 操作步骤

1. 打开 `/data-preview`。
2. 将鼠标移动到左侧对象树右边界。
3. 按住边界向左拖拽到很窄。
4. 松开鼠标。
5. 再次从窄栏右边界按住向右拖拽。
6. 松开鼠标。

#### 预期结果

- 侧栏默认宽度约 288px。
- 向左拖到阈值后，侧栏吸附为约 42px 窄栏，只保留最小对象树入口，不出现 50-70px 的半折叠挤压状态。
- 窄栏向右拖过阈值后，侧栏恢复为至少 220px 的可读宽度。
- 拖拽时数据网格同步占满剩余空间。
- 拖拽过程中不出现浏览器原生 resize 与自定义拖拽同时生效导致的抖动。

### TC-REAL-P0-006C 最近打开与主框架遮挡

#### 目标

验证左侧“最近打开”不是无效提示，且数据预览页面不会被 Dolphin 顶部菜单遮挡。

#### 操作步骤

1. 打开 `/data-preview`。
2. 从左侧对象树依次点击 2-3 张不同的表。
3. 查看“最近打开”区域。
4. 点击“最近打开”中的非当前表。
5. 查看页面顶部工具栏与 Dolphin 顶部菜单的关系。

#### 预期结果

- 最近打开区域展示真实打开过的表。
- 最近打开记录可以点击。
- 点击最近打开记录后，中间表标签切换到对应表，右侧数据网格加载对应数据。
- 当前最近记录有高亮状态。
- 顶部工具栏、数据源选择器、数据库选择器、左侧搜索框完整可见，不被 Dolphin 顶部菜单遮挡。
- 页面四边不应被 Dolphin 内容容器裁切，底部状态栏、左侧对象树底部状态、右侧表格边界都必须完整可见。
- 数据预览不应被默认内容 padding 包成表单页样式，工作台应自然占满 Dolphin 内容区。

### TC-REAL-P0-006D 左侧对象树紧凑展开

#### 目标

验证左侧库表树接近成熟数据库工具的紧凑对象树体验，而不是松散列表。

#### 操作步骤

1. 打开 `/data-preview`。
2. 查看左侧数据源、数据库、表分组、表节点。
3. 依次点击数据源、数据库、表分组左侧展开箭头。
4. 再次展开这些节点。
5. 点击一张表。

#### 预期结果

- 节点为单行紧凑展示，表节点不再使用两行大块布局。
- 数据源、数据库、表分组均支持展开 / 收起。
- 收起父节点后子节点隐藏，重新展开后当前表选择状态不丢失。
- 表分组右侧展示表数量。
- 当前表使用浅蓝背景和左侧强调线高亮。
- 对象树整体在 288px 宽度下能显示更多表项，不显得松散。
- 数据源连接节点能识别 MySQL / PostgreSQL 类型，不使用无意义圆点或方块。
- 数据库节点、表节点、视图节点图标具备对象语义。

### TC-REAL-P0-007 查询失败与空结果

#### 目标

失败和空结果不是白屏或静默失败。

#### 操作步骤

1. 设置一个必然查不到数据的筛选条件并执行查询。
2. 再设置一个非法或后端拒绝的查询条件并执行查询。

#### 预期结果

- 空结果时表格区域展示“当前条件无数据”。
- 查询失败时页面展示可见错误提示条。
- WHERE、ORDER BY、复制 SQL 区域仍保留当前配置，方便用户修正。

### TC-REAL-P1-001 查询安全限制

#### 目标

前端不能提交任意 SQL；后端拒绝未知字段、非法表名、超过 200 的 pageSize。

## 13. 交付时必须说明的测试结论

每次交付时必须明确反馈：

- 实际执行了哪些用例编号
- 哪些用例通过
- 哪些用例未执行及原因
- 是否执行了原生功能保护测试
- 是否发现并修复问题

## 14. 后续维护建议

后续每新增一个功能点，都应同步补一条测试用例。

原则是：

- 功能需求文档定义“要做什么”
- 页面原型文档定义“怎么用”
- 测试用例文档定义“怎么验”

三者必须一起维护，后续开发才会稳定。
